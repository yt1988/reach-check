# Reach Check 可达性检测

[English](README.md) · **简体中文**

别人能连上你的网站、NAS 或游戏服务吗？连不上的话，卡在哪一步？[可达性检测](https://reach.1ms.dog) 从全球 18 个地区（含中国电信、联通、移动）去连你的服务，再从你自己的浏览器连一次。每个地区分段显示 DNS、TCP、TLS、首字节耗时；连不上就指出停在哪一步、下一步查哪里。

**线上地址：** https://reach.1ms.dog（原型，尚未部署）

## 检测什么

- **从 18 个地区连过去**：每个地区一个 [Globalping](https://globalping.io) 探针，分布在中国大陆三网、香港、台湾、东京、韩国、新加坡、印度、澳大利亚、伦敦、法兰克福、俄罗斯、阿联酋、南非、洛杉矶、纽约、圣保罗。每个探针向这个端口发一次 HTTP(S) 请求，能分清这几种结果：
  - 网页正常返回；
  - 端口开着，但不是网页服务（SSH、Minecraft……）；
  - 拒绝连接：没有程序在监听；
  - 超时：被防火墙丢掉了，或者没做端口转发；
  - DNS 解析失败、连接被重置、TLS 握手失败。
- **从你的浏览器连过去**：对同一个地址发两次 HTTPS 请求。浏览器只能看到请求多久后失败，所以能分清"完全没有回应"和"有东西回应了"；对 HTTPS 网页，还能把耗时拆成"建立连接"和"请求"两段。浏览器不允许连的端口（22、25、110……）会直接说明。
- **DNS**：
  - 从浏览器通过 DoH 查阿里 DNS、Cloudflare、Google 的答案，并做对照；
  - 发现公网记录里填了内网地址或运营商级 NAT 地址；
  - 发现域名开着 Cloudflare 代理（它只转发少数几个 HTTP 端口）；
  - 发现各家解析服务答案不一致，或者中国大陆探针解析到的地址和其他地区不同。
- **结论和下一步**，覆盖这些常见原因：
  - 端口转发、防火墙；
  - 没有公网 IPv4（CGNAT）；
  - 家宽封了常用端口；
  - 服务只监听了 127.0.0.1；
  - Cloudflare 52x 错误、证书问题；
  - TCP 握手慢（丢包重传）；
  - 你自己看到的和外面看到的不一致（NAT 回环、代理）。
- 失败的地区可以点**追踪路由**。还有**邀请链接**：朋友打开后，用他的浏览器连你的服务。

UDP 端口（很多游戏服务器、WireGuard）测不了：浏览器和公共探针都没有通用的办法判断 UDP 端口开没开。

## 在哪里运行

全部在访客的浏览器里运行。页面直接调用 Globalping 的接口，每个访客用自己的额度：每个 IP 每小时 250 个探针结果，一次检测用 18 个。额度用完时，页面会告诉你多久后恢复。站点只有静态文件，你测了什么，没有任何服务器知道。

## 开发

```bash
npm run dev        # http://localhost:8787，带上线时同样的响应头（public/_headers）
```

用 `npx wrangler deploy` 部署（只有静态资源，不计请求数），然后在 Cloudflare 控制台绑定域名。

```
public/index.html   页面
public/app.js       地区、Globalping、浏览器检测、DNS、结论
public/style.css    设计变量（和其他 1ms.dog 工具一致）和布局
scripts/dev.mjs     本地预览服务器
```
