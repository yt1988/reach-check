        常見問題

        是怎麼檢測的？

        Globalping 在 18 個地區的志工探測點，各自連到你的位址和連接埠，送出一次 HTTP(S) 請求，並替每一步計時：DNS 解析、TCP 交握、TLS 交握、第一個位元組。失敗時，錯誤訊息會說明停在哪一步：拒絕連線、逾時、被重設、TLS 出錯，或連接埠上的不是網頁服務。

        你自己的瀏覽器也會連一次，結果在表格第一列。這些請求都不經過我們的伺服器。

        我自己打得開，為什麼別人連不上？

        如果你和服務在同一個網路裡，流量根本沒有出去，自己打得開不代表外面連得上。開著代理時，你走的路也和別人不同。請以外部檢測為準：它和陌生人連線的方式一樣。

        連接埠轉送設好了，為什麼還是逾時？

        常見原因：沒有公開的 IPv4（路由器的 WAN 位址以 100.64–100.127 開頭，或和你的公開 IP 不同，就是電信業者級 NAT）；NAS、Windows 或雲端安全群組的防火牆沒有放行；電信業者封鎖家用寬頻的 80、443 等常用連接埠；轉送指向的還是設備以前的內部 IP。

        使用 IPv6 時，路由器和數據機的 IPv6 防火牆預設擋下連入連線，要另外放行這個連接埠。

        「拒絕連線」和「逾時」有什麼不同？

        拒絕連線：封包到了那台機器，但連接埠上沒有程式在接聽。可能是服務沒開、只在 127.0.0.1 上接聽，或轉送到錯誤的連接埠。

        逾時：完全沒有回應。可能是防火牆丟掉了封包、沒有設定連接埠轉送，或位址填錯了。

        能測遊戲或 WireGuard 用的 UDP 連接埠嗎？

        不能。UDP 服務收不到正確的訊息時通常不會回應，所以瀏覽器和公開探測點都沒有通用的方法判斷 UDP 連接埠有沒有開。可以先確認主機透過 TCP 連得上（選 SSH 或網頁連接埠），再請朋友直接用遊戲連線。

        我填的位址誰看得到？

        執行探測的 Globalping。我們不會保存。結果連結裡帶著位址和結果，讓別人看到同一次檢測；連結裡不會有你自己的 IP。

        每個 IP 在 Globalping 每小時可以測 250 個地區次，一次檢測用 18 個；用完時頁面會告訴你多久後恢復。
